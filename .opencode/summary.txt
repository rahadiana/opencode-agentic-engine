## Fakta Penting

### Model Resolution Architecture
- `callOpenCode()` ONLY routes through OpenCode SDK (no direct HTTP calls)
- `detectProvider()` always returns "opencode"
- `LLMRequest` punya field `model?: { providerID, modelID }`
- `LLMRequest` punya field `toolName?: string` — untuk auto model resolution
- `parseModelForSDK()` helper: parse "providerID/modelID" → `{ providerID, modelID }`
- Jika format tanpa "/" → providerID = "opencode" (auto-resolve)
- Jika model tidak di-set → SDK body.model tidak dikirim → OpenCode pakai session default

### 3-Level Model Resolution (Per-Tool)
- **Priority 1**: `req.model` explicit (per-call)
- **Priority 2**: Per-tool override (`agentic_model set tool=X model="Y"`)
- **Priority 3**: Category by complexity (`agentic_model set category=quick model="Y"`)
  - Tiap tool punya `complexityTier` bawaan (quick/unspecified-low/unspecified-high/deep)
  - `TOOL_COMPLEXITY` map di `llm.ts`
- **Priority 4**: Per-role (via `agentic_delegate` → `agentRuntime.execute()`)
- **Priority 5**: Engine default (`engine.config.model`)

### Implementasi
- `sessionStore` punya 3 namespace: `modelPreferences` (role), `toolModelPreferences` (tool), `categoryModelPreferences` (category)
- `LLMEngine` punya `_toolContext` — diset tiap tool handler via `setToolContext()`
- Tiap tool handler yang panggil LLM set `llmEngine.setToolContext('agentic_xxx')`
- `call()` resolve model: `req.model ?? _toolContext → toolPref → categoryPref → parseModelForSDK()`
- `.agentic/models.json` struktur baru: `{ "developer": "...", "tools": {...}, "categories": {...} }`
- `agentic_model` handler diperluas: terima `tool` dan `category` params
- Role sekarang **dynamic** — validasi dihapus, semua string diterima

### Agent Runtime
- `AgentContext` punya `modelPreference?: string`
- `agentRuntime.execute()` → `engine.updateConfig({ model })` sebelum call
- `agentic_delegate` membaca `sessionStore.getModelPreference()` dan apply ke agentCtx
